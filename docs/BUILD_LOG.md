# mcp-reality-check build log

The full narrative history of how `mcp-reality-check` was built, dogfooded and fixed: what each real-world run found and what changed because of it. It moved here from the [profile README](https://github.com/vishalhabib99) on 2026-09-23 so the profile stays short. The text is unchanged.

completes the trilogy (`pip install mcp-reality-check`): mcp-doctor asks *is it documented*, mcp-fuzz asks *does it fail safely*, this asks *does it actually work*. Calls each tool once with a realistic (not placeholder) input and checks the response for a refusal disguised as success ("I don't have access to..." wrapped in `isError: false`), empty content on a claimed success, and violations of a tool's own declared output schema — all fully deterministic, no LLM judge, no API key, no per-call cost. 18+ real-world passes so far, most recently corroborating a clean `mcp-fuzz` pass on `arabold/docs-mcp-server` — found and fixed a real bug in its own input generator (a missing "timezone" hint broke every call to `mcp-server-time`), then hardened the same generator against the malformed-metadata bug class found in mcp-fuzz. Everything else clean. Also corroborated the same `oraios/serena` LSP-backed run as mcp-fuzz above: 10/10 checkable tools, 0 flagged, 100%/A. Most recently, found a real bug in itself while dogfooding `sooperset/mcp-atlassian`: no `--env` flag existed at all, so any config-gated server (this one registers zero tools without Jira/Confluence credentials) was silently untestable — `mcp-fuzz` had already solved the identical problem months earlier for `brave-search-mcp-server`. Added `--env`, re-verified: 58 tested/40 skipped, matching `mcp-fuzz`'s count exactly, 100%/A. Most recently, turned the same checks into a live runtime gate (`guarded_call`, v0.3.0) — instead of only a one-shot batch audit, an agent can now run every real tool call it makes through the same refusal/empty-content/schema-violation checks at call time, catching a lying-but-successful response before it reaches the agent's context. Deliberately scoped to correctness, not security — the runtime-security-proxy space (secrets, prompt injection, destructive-command policy) already has real, actively-maintained tooling elsewhere; this answers a different question that space doesn't: a call can be perfectly safe and still misrepresent what it did. Verified against a real crash and a real timeout (two new fixture tools, not mocked) and dogfooded live against the official `@modelcontextprotocol/server-memory` reference server — a real `create_entities` call and a real `read_graph` call, both correctly passing unflagged. Most recently, added **Streamable HTTP support** (`--url`/`--header`) alongside stdio, mirroring `mcp-fuzz`'s identical fix — including the same real robustness bug: a reconnect-after-failure that itself fails (expected the moment a tool kills a remote server this tool doesn't own) used to crash the whole run instead of being reported. Verified against the same real external target as `mcp-fuzz`: [`WillDent/pipedrive-mcp-server`](https://github.com/WillDent/pipedrive-mcp-server) over real HTTP with a real auth header — 16/16 tools connected, correctly 0/16 checkable (every call honestly returns `isError: true` against a dummy token, not a disguised failure). Released as `v0.4.0`.
